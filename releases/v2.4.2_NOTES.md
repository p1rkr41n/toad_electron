# Toad v2.4.2 Release Notes

## Three-Way Startup Reconciliation Engine & 5-Character Project ID Ledger

### Overview
Toad v2.4.2 introduces deep enterprise-grade resilience and zero-cost project organization:
1. **5-Character Collision-Free Project IDs**: Project IDs are strictly generated as 5-character lowercase alphanumeric strings `[a-z0-9]{5}` (e.g. `grj3c`, `u8x2m`), preventing Windows filesystem character issues and completely decoupling physical cache folders from user-facing display names (`project_name`).
2. **Independent Cache Partitions (`temp/<project_id>/`)**: Each project owns its own physical cache subfolder on disk. Renaming a project is a metadata-only operation with zero disk I/O and zero risk of `EBUSY` file locking errors.
3. **Typed NULL Tombstone Architecture**: Project deletions and missing folder scenarios record schema-safe `CAST(NULL AS <Type>)` tombstone entries into the Parquet WAL ledger, followed by view unmounting, atomic directory renaming to `.trash_*`, and non-blocking asynchronous disk cleanup.
4. **DuckDB Window Function Project State Tracking**: Real-time project lifecycle status is computed using `ROW_NUMBER() OVER (PARTITION BY project_id ORDER BY timestamp DESC)` directly from `toad_ledger.parquet`.
5. **Safe Ledger Reset on Complete Deletion**: When all projects are deleted (0 active projects), the physical Parquet ledger is safely unlinked and recreated as a pristine 0-row Parquet file, followed by automatic generation of a fresh `Untitled-1` project with a new 5-character ID.
6. **Three-Way Startup Reconciliation Engine**: Comprehensive self-healing engine on startup that synchronizes Parquet Ledger (SSOT), Temp Cache (`temp/<project_id>/`), and Source Disk across all 6 scenarios, including recursive subfolder scanning and foreign orphan cache pruning.
