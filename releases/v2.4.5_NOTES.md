# Toad v2.4.5 Release Notes

## Zero-Assertion DuckDB Ingest Engine, Complex Log Safe Profile & Out-of-Process Worker Sandbox

### Overview
Toad v2.4.5 delivers a resilient, crash-immune ingestion architecture that eradicates the native C++ assertion error (`vector.cpp:1859: vector.GetType().InternalType() == PhysicalType::VARCHAR`) when importing forensic, security, and mixed-type data (e.g. Hayabusa CSV, Windows Event Logs, Sysmon, Audit dumps, or bulk folder imports).

### Core Architectural Upgrades

1. **Root-Cause Elimination (RFC-4180 `escape = ''` Across All Query Tiers)**:
   - Eliminated the hazardous `escape = '"'` parameter in DuckDB CSV import queries.
   - Setting `escape = ''` completely prevents DuckDB's native parser from invoking `StringVector::EmptyString(vector)` and `StringValueScanner::RemoveEscape` on vectors inferred as non-VARCHAR (`PhysicalType::INT64`).
   - Ensures DuckDB never trips the fatal MSVCRT `assert()` dialog.

2. **Complex Log / DFIR Safe Ingest Profile (`all_varchar = true`)**:
   - Implemented heuristic classifier `isComplexLogFile(filePath)` recognizing forensic tools, security logs, timeline dumps, and heterogeneous data structures:
     - Keywords: `hayabusa`, `eventlog`, `event_log`, `security`, `sysmon`, `audit`, `mft`, `timeline`, `evtx`, `edr`, `trace`, `dump`, `incident`, `forensic`, `timelineexplorer`.
     - File extensions: `.log`, `.txt` and encoded filenames.
   - For complex log datasets, Toad automatically skips tentative type guessing and streams directly via `all_varchar = true`.
   - Mathematical guarantee: Because every column has physical type `PhysicalType::VARCHAR`, the assertion condition `vector.GetType().InternalType() == PhysicalType::VARCHAR` is universally `TRUE` (0% possibility of assertion failure).
   - Preserves complete data fidelity for forensic analysis: leading zeros, hex codes, hash signatures, and raw timestamps remain pristine without truncation or scientific notation distortion.

3. **Out-of-Process Worker Sandbox (`ingestWorker.ts` / `ingestWorker.js`)**:
   - Packaged a standalone worker process (`child_process.fork`) for streaming CSV and log files to DuckDB Parquet.
   - Complete crash isolation: even if an unhandled hardware or native C++ fault occurs within the DuckDB engine, only the isolated worker child process terminates; the primary Electron application, UI DataGrid, and project sidebar stay 100% operational.
   - Graceful fallback: If an out-of-process worker encounters an error, the main process catches exit codes cleanly and logs file failures with visual status markers rather than crashing the window.

4. **Folder Bulk Ingest Throttling & Priority**:
   - In `addFolderToProject()`, files detected as complex logs are pre-tagged with `{ isComplexLog: true }`.
   - `MultipleLoadingManager` queues files with dynamic resource budgeting and sequential background execution, preventing CPU and disk lock starvation when opening large forensic folders.

5. **Deep Integration QA SUITE LL**:
   - Added `SUITE LL` (LL.1 through LL.6) to `tests/deep_integration_qa.js`.
   - Validates `isComplexLogFile()` heuristics, zero-assertion query profiles, dirty/mixed numeric-and-quoted CSV ingestion resilience, standalone `ingestWorker.js` execution, and system-wide v2.4.5 synchronization.
