## TOAD v2.5.0: Electron utilityProcess Architectural Migration & Tauri-like Host Bridge

TOAD v2.5.0 delivers a major architectural leap: decoupling the database engine, Parquet Ledger, and ingestion pipeline entirely from both the Main and Renderer processes into an isolated **Electron `utilityProcess`**, communicating via a high-speed **MessagePort** channel with a zero-copy **Hybrid Protocol** and supervised auto-recovery.

---

## Key Highlights & Architectural Enhancements

### 1. Dedicated Engine Service (`utilityProcess`)
- Complete isolation of DuckDB C++ native driver (`duckdb.node`), connection pooling, and background ingestion pipeline into an independent Electron `utilityProcess` (`engineService.ts`).
- Chromium Renderer hardened with `contextIsolation: true` and `nodeIntegration: false`, eliminating the risk of entire-app crashes (white screen) if heavy native queries encounter unexpected assertion or out-of-memory errors.

### 2. Standardized Tauri-like Host Bridge & CLI Test Compatibility
- Standardized all frontend communications through `window.toadBridge.invoke(command, payload)` exposed safely by `preload.js`. Prepares 100% of the UI codebase for seamless future migration to Tauri v2 (Rust + WebView2).
- Implemented `HeadlessNodeAdapter` in `packages/host-bridge` to allow CLI test runners (`run_tests.js`, `deep_integration_qa.js`) to execute directly against the engine without requiring an Electron graphical display.

### 3. High-Performance Hybrid Data Protocol (Zero-Copy)
- Tabular query results transfer over a direct `MessagePort` connecting Renderer and `utilityProcess`.
- Metadata, schemas, and counts are serialized as structured JSON DTOs, while dense tabular row/column data blocks are packed into binary transferable `ArrayBuffer` objects with the `'TOAD'` magic wire header, bypassing expensive JSON serialization and achieving **2.28 ms/query** average latency across 1,000 queries.

### 4. Supervised Auto-Restart & Parquet Ledger Recovery (< 500ms SLA)
- Main process acts as Supervisor (`engineSupervisor.ts`), monitoring child process lifecycle.
- In the event of a crash or SIGKILL, the supervisor automatically forks a new engine in **~265 ms** (SLA < 500 ms) and replays registered table views from `toad_ledger.parquet` in **~2.4 ms/view** (SLA < 5 ms).
- Renderer displays a non-blocking BlueprintJS toast notification: *"Động cơ phân tích vừa được tự động phục hồi"* and automatically reconciles active views without data loss.

### 5. Dual-Mode Engine Configuration
- Added persistent engine selection in `config.ini` (`runtime.engine = "utility" | "legacy"`), allowing instant fallback to legacy in-process engine mode if needed.

### 6. Production Packaging & Budget Enforcement
- Webpack bundle for `engineService.bundle.js` (`target: "node"`, 12.6 KiB).
- `app.asar` footprint maintained at **25.80 MB** (strictly below 45 MB budget).
- Portable executable size maintained at **72.11 MB** (strictly below 75 MB budget).
- Zero-Duplicate Binary Storage policy strictly enforced.
