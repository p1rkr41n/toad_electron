### Key Highlights & Summary

TOAD v2.5.2.1 delivers configurable Safe Mode ingestion keywords via `config.ini`, dynamic multi-threaded DuckDB CSV/TSV ingestion, default exclusion of NTFS MFT dumps from memory-heavy text mode, non-destructive configuration auto-healing, and strict restoration of the canonical Electron desktop runtime core.

#### 1. Configurable Safe Mode Keywords via `config.ini`
- **Dynamic Keyword Array:** Moved the hardcoded `complexKeywords` list into the user-editable `config.ini` under the `[duckdb]` section (`safe_mode_keywords = hayabusa, eventlog, ...`).
- **User Customization:** Users can freely edit, add custom forensic log keywords, or disable Safe Mode entirely using `none` or `off`.
- **Non-Destructive Auto-Healing:** Automatically validates and restores missing keys without altering or losing other user customizations in `config.ini`.

#### 2. NTFS MFT Performance Optimization (Fix for 40GB Slowdown & 24GB RAM Balloon)
- **Default MFT Exclusion:** Removed `"mft"` from the default `safe_mode_keywords` list.
- **Native Fast Parallel Mode:** Files such as `Windows.NTFS.MFT.csv` (40GB+) now stream directly into DuckDB across all CPU cores (`parallel = true`), utilizing columnar integer type inference instead of 2+ billion C++ `StringHeap` objects, reducing memory usage from ~24GB down to optimal sub-gigabyte levels.
- **Opt-in Safety:** Users analyzing corrupted or malformed MFT extractions can re-enable Safe Mode simply by adding `, mft` to `config.ini`.

#### 3. Dynamic Parallelism in Safe Mode (`safe_mode_parallel`)
- **Multi-Threaded Safe Profile:** Added `safe_mode_parallel = true` under `[duckdb]`. Complex security log files (Hayabusa, Sysmon, EventLog) retain VARCHAR assertion protection (`all_varchar = true`) while utilizing all available CPU threads for a 15x–20x throughput improvement.
- **Graceful Multi-Tier Fallback:** Automatically falls back to single-threaded ingestion if malformed lines exceed chunk boundaries.

#### 4. Canonical Electron Core Runtime Restoration
- **Verified Electron Architecture:** Built using Electron 31, Node.js 18, and `duckdb.node` native bindings packaged within `app.asar.unpacked`.
- **Strict Single-Binary Packaging:** Packaged via `dist_package.ps1` with zero duplicate binaries, complete Windows PE resource metadata branding, and clean process lifecycle.
