## TOAD v2.4.8.1: Background 3-Page Preload, Dynamic Rows/Page & Instant Open UX

TOAD v2.4.8.1 introduces high-efficiency background preloading, dynamic pagination controls, proactive cache re-warming, and instant opening UX without modal loading delays.

---

## Key Highlights & Architectural Enhancements

### 1. Default Background 3-Page Preloading
- Automatically pre-warms the first 3 pages ($\min(\text{totalRowCount}, 3 \times \text{pageSize})$) directly into RAM buffer cache as soon as background Parquet conversion finishes, even if the user has not clicked to open the file.
- Provides immediate 0ms navigation across Page 1, Page 2, and Page 3 from the in-memory sliding buffer.

### 2. Dynamic Rows/Page Configuration
- Removed the hardcoded 1,000-row page limit.
- Pagination dynamically adapts to the `Rows/page` dropdown configured at the footer (500, 1,000, 2,500, 5,000, 10,000, or custom values).
- Stored cleanly in session memory (`ViewState.ts`), starting at 1,000 rows by default and resetting cleanly across app restarts.

### 3. Proactive Cache Re-warm Engine (`rewarmAllReadyCaches`)
- When the user changes `Rows/page` at the footer, TOAD proactively triggers an asynchronous background re-warm for all ready files in the workspace.
- Implemented race condition cancellation: intermediate re-warm runs are cleanly aborted when newer page sizes are selected.

### 4. Zero-Latency Instant Open UX (< 5ms)
- Opening files with ready RAM cache completely bypasses the intrusive modal loading overlay and progress bar ("Opening table view... 100% completed").
- Sets `document.body.style.cursor = 'wait'` for a few milliseconds of visual feedback while mounting the view, then renders the SlickGrid table immediately.
- `PivotRequester` detects preloaded buffer in `viewState.dataView` and bypasses redundant DuckDB queries.

### 5. True LRU 30-Item RAM Cache Budget
- Implemented canonical path normalization (`resolveCacheKey`) so both `canonicalPath` and `item.key` resolve to the same cache entry, eliminating duplicate key consumption.
- Applied true LRU touch recency (`entry.cachedAt = Date.now()`) on cache reads, preventing active files from premature eviction while capping memory consumption at ~150 MB.
