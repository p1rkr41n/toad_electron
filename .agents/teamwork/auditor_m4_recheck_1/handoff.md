## 3. Caveats

- **Asynchronous Trash Cleanup**: On Windows NTFS, if an external process holds an open file without `FILE_SHARE_DELETE`, the file remains temporarily in `.trash_*` until the handle is closed, at which point the async retry loop purges it. This is standard Win32 filesystem behavior and does not block the caller.
- **WAL Writes**: WAL appending continues to use DuckDB in background worker threads, which ensures full ACID durability while reads are accelerated via native Arrow/Parquet readers.
